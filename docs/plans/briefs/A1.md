## Como trabalhar
- Ambiente: `npm run db:reset` (slot 1, já configurado) após cada mudança de migração/seed. **Nunca** rode `supabase` direto nem toque nas portas 545xx.
- Só edite arquivos do Agente A (ver `agent-ownership.md`). Migrações antigas: **não editar**.
- Ao concluir, rode: `npm run typecheck && npm run lint && npm run test:unit && npm run test:db` — **todos** devem passar (os testes existentes também; se algum existente quebrar por causa do seed, ajuste o **seed**, não o teste, e relate).
- Não rode e2e nem build (economia de memória; o coordenador roda).
- Commit local: `[A1] Contrato de dados: execuções, ações e conversas` (sem push, sem merge).
- Relatório: `docs/reports/a-A1.md` (arquivos, funcionalidades, testes + resultados, riscos/bloqueios, hash).
- Atualize o status: `orca worktree set --worktree active --comment "A1: <estado>" --json`.
- Dúvida de regra comercial não coberta pela especificação: **não invente**; registre no relatório como bloqueio e siga com o restante.
